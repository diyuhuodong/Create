# Create Bedrock 动力视觉改造方案

## 目标与范围

本方案解决 Create Bedrock 的动力方块在 Bedrock 中的高还原度静态外观、轴向、旋转动画、齿轮传动相位和世界重载稳定性问题。

本轮不重写现有的 `KineticWorld` 动力网络。它已经承担方块放置和拆除、网络重算、皮带连接、源速度、变速、持久化，并向加工、流体、机械臂等模块提供 `speedAt()`。改造范围是其上方的**相位和视觉投影层**。

第一个完整试点为创造马达；成功后按轴、齿轮、传动、机器的顺序迁移。

## 已确认的现状

### 当前项目

- `bedrock/behavior_pack/scripts/kinetics/kinetic-world.js` 保存动力节点、连接、来源速度和持久化快照，并在脏维度上重新解析网络。
- `speedAt()` 已被多个非动力模块使用；替换网络实现会造成大范围回归风险。
- 当前创造马达视觉曾将外壳、轴和轴端拆成不同视觉部件。它们的根朝向、局部旋转和生命周期不一致，会产生轴短、变向后突然变长、部件不能作为整体变化等问题。

### Java Create 基准

- 创造马达的外壳是静态模型。
- 可见轴是独立的半轴 partial model；它的方向由方块 `FACING` 决定。
- 扳手对控制面执行配置，对其他可操作面调整输出方向。
- Java 客户端使用 Flywheel partial model，静态外壳与旋转轴拥有明确的父子/局部变换关系。

### Steam & Gears 参考结论

Steam & Gears 证明 Bedrock 的 Script API、实体骨骼和客户端动画可实现旋转动力网络。它值得借鉴的关键不是某一段脚本，而是整体实体骨架：

```text
动力网络（RPM、方向、倍率）
        ↓
视觉投影（实体记录、相位、重建策略）
        ↓
一个视觉实体
  ├─ 根骨骼：机器整体朝向
  ├─ 静态骨骼：外壳
  └─ 旋转骨骼：轴或转子
```

其轴模型使用单一几何、单一纹理和单一渲染控制器；父骨骼负责朝向，子骨骼负责旋转。因此模型不会分裂为彼此不同步的多个实体。

不直接照搬其实现：它的连接规则存在重复定义，节点类型依赖大量布尔字段，拓扑变化会较重地重生实体；压力逻辑需独立验证。项目应借鉴结构，重新实现代码与美术资源。

## 目标架构

### 1. 动力真值层：保留并扩展 KineticWorld

在现有节点解析结果上增加只读的视觉状态：

```js
{
  rpm,             // 已有的网络转速，含方向
  phase,           // 0..360 的服务器权威旋转相位
  axis,             // x / y / z
  facing,           // 机器输出朝向
  networkRevision,  // 拓扑或传动关系变更版本
  visualRevision    // 需要客户端重建时递增
}
```

相位规则：

- 每个动力网络以服务器 tick 推进相位；客户端只做两次同步之间的平滑插值。
- 网络重连时，沿传动边按倍率、方向和齿相位差传播相位。
- 只有 RPM 变化时更新实体属性，不重新生成实体。
- 只有方块种类、朝向、模型变体或网络拓扑变化时才重建/重新定相视觉实体。

### 2. 连接描述：单一声明来源

为每种动力方块定义一个 `KineticDescriptor`，使连接、倍率和视觉不再分散在多个 if/else 中：

```js
{
  id: "createbedrock:creative_motor",
  ports: [/* 轴向或面向端口 */],
  transfers: [/* 输入端口到输出端口、倍率与反向 */],
  source: { defaultRpm: 16, configurable: true },
  visual: {
    kind: "whole_entity",
    entityType: "createbedrock:creative_motor_visual_v2",
    modelFamily: "creative_motor"
  }
}
```

图连接解析只读取这份描述。视觉层也读取其中的 `visual` 字段，避免网络规则与渲染规则再次分叉。

### 3. 整体视觉实体：一台机器一个骨架

创造马达的 v2 实体必须拥有：

```text
motor_root             机器位置和 FACING 朝向
├─ motor_casing         Java 原始外壳模型，永不旋转
├─ motor_panel          显示面与文字，永不旋转
└─ motor_shaft          Java shaft_half，绕本地轴旋转
```

- 模型使用单一几何和单一渲染控制器。
- 所有 Java Create 材质合并为自动生成的纹理图集；保留模型比例、UV 和像素设计。
- 方块本体在视觉实体准备完成后隐藏；实体销毁、远离、重进世界或异常恢复时必须重新显示/恢复，避免空气洞或重影。
- 不能再让“外壳、轴、端盖”以独立实体或独立渲染控制器拼装。

### 4. 视觉实体生命周期

视觉注册表以 `dimension + block location + visual schema version` 作为稳定身份：

1. 放置方块：创建或恢复一个实体，写入朝向、RPM、方向、相位和 schema 版本。
2. 仅速度改变：更新实体属性；不重生。
3. 方块旋转、模型状态或网络拓扑改变：按相位重建，静态方块和实体切换必须原子化。
4. 加载世界：扫描持久化节点恢复缺失实体；删除位置相同但 schema 过期的实体。
5. 方块拆除：删除实体、清除注册记录、恢复方块可见状态。
6. 周期性审计仅用于灾难恢复，不能每 5 tick 扫描并重建所有节点。

## 实施分期

### P0：冻结旧试验实现

- 不再在创造马达 v0.1.51 的拆分部件方案上做视觉补丁。
- 将旧视觉实体视为迁移源，仅保留安全清理兼容代码。
- 制定 v2 schema 版本和世界迁移策略。

### P1：建立视觉投影 v2 基础设施

- 新建视觉实体注册表、相位存储和事件驱动同步器。
- 给 `KineticWorld` 增加网络级相位及拓扑 revision 的可查询接口。
- 增加节点—实体清理、重载恢复和版本迁移测试。

### P2：创造马达完整试点

- 从 Java 原始模型转换完整外壳、控制面和半轴。
- 生成单一纹理图集与单一实体几何。
- 生成 `motor_root → casing/panel/shaft` 骨架和对应动画。
- 接入扳手：控制面配置；其他面调整输出轴方向。
- 完成六向放置和重进世界验收后，旧马达视觉下线。

### P3：基础传动视觉

按以下顺序迁移，每项都先完成模型、连接、相位和实机验证：

1. 轴；
2. 小齿轮；
3. 大齿轮；
4. 齿轮箱；
5. 离合器、变速器和皮带。

目标是覆盖同轴、垂直啮合、正反转、大小齿轮 2:1、断连与重连。

### P4：工作机器视觉

在基础传动稳定后，依次迁移具有独立旋转件的机器：

- 粉碎轮及控制器；
- 鼓风机；
- 压机、搅拌器、锯和钻头；
- 其他处理机器。

每个机器先标记 Java 中静态和旋转 partial model，再生成 Bedrock 骨架；不能仅按方块名称套用同一个模型。

### P5：复杂结构与性能

- 多方块结构、移动结构、列车挂接/拆解；
- 距离裁剪和缺失实体恢复；
- 大型网络下的属性更新批处理；
- 压力、冲突与停机时的视觉同步。

## 模型转换工具改造

扩展 `bedrock/tools/convert-java-models.mjs`，使其输出视觉契约而不仅是 JSON：

```json
{
  "modelFamily": "creative_motor",
  "staticBones": ["motor_casing", "motor_panel"],
  "rotatingBones": [{ "bone": "motor_shaft", "axis": "local_y" }],
  "facing": true,
  "materials": ["creative_casing", "creative_motor", "flap_display_front", "axis"],
  "textureAtlas": "textures/entity/createbedrock/kinetics/creative_motor.png"
}
```

生成器还必须验证：

- 每个视觉族有且仅有一个实体几何根；
- 旋转骨骼是静态根的子级；
- Java 模型的尺寸、轴心、UV 和面材质均可追溯；
- 生成的实体、几何、动画、控制器和纹理图集具有一致名称。

## 测试与验收

### 自动测试

- `KineticWorld`：速度、方向、倍率、冲突、拆除、重连和持久化。
- 相位：同轴同步、齿轮反向、大小齿轮 2:1、断开静止、重连不跳变。
- 视觉契约：单实体、单骨架、骨骼层级、材质图集、六向映射。
- 生命周期：实体缺失恢复、旧 schema 清理、世界重载、拆方块清理。
- 包构建：模型转换、静态契约、资源清单和 `.mcaddon` 内容校验。

### Bedrock 实机验收

1. 创造马达六个方向均与 Java Create 的外壳、文字和轴位置匹配。
2. 轴在正确位置、长度和方向上连续旋转；外壳不随之旋转。
3. 扳手作用在控制面和其他可操作面时分别执行正确动作。
4. 轴、小齿轮、大齿轮接入马达后速度、方向和齿相正确。
5. 拆除/重放、离开再返回、退出再进入世界后不重影、不消失、不产生空气洞。
6. 更改 RPM、离合器、变速器或网络连接时平滑变化，无实体闪烁或重生跳帧。
7. 压力不足、冲突或停机时，所有相关视觉同步停止。

## 参考与许可边界

- Java Create：本项目已有的原始模型、材质、方块语义与交互行为是还原基准。
- Steam & Gears：作为 Bedrock 实体骨骼、相位记忆、网络实体生命周期的架构参考；不复制代码和资源。其发布页面标明 EPL-2.0，若未来需要直接复用具体代码，必须先单独进行许可证与归属审查。
- Mojang Bedrock 文档：实体模型和动画支持通过骨骼层级分离整体朝向与局部旋转，是 v2 方案的技术基础。

## 完成定义

创造马达不再依赖拆分视觉部件；它以一个整体实体呈现与 Java Create 对应的外壳、面板和轴，在全部朝向、网络变化和世界重载场景下稳定工作。随后以同一套 v2 契约迁移轴和齿轮，避免为每个方块重新发明渲染机制。
