# C2 持久化内容设计

## 目标

C2 覆盖 S3-14 依赖的时钟、铃、显示与仪表、门、汽笛、库存设备和玫瑰石英灯。每个方块必须同时交付行为包、状态/持久化运行时、Java 资源、掉落/真实获取路径和 EN/ZH；没有行为不得创建空壳定义。

## 顺序

1. **C2-A 交互输出**：桌面铃、玫瑰石英灯、库存开关。先建立可重用的方向、原生红石、计时和资源契约。
2. **C2-B 可视状态**：速度计、应力计、展示板、告示牌、翻页显示器、Stock Ticker；复用已存在的动力/物流/显示持久化服务和显示实体。
3. **C2-C 时间与铃**：两种布谷钟、奇异/闹鬼铃。时钟由动力速度和世界时间驱动；闹鬼铃的半径脉冲、冷却、转化和粒子必须服务器权威。
4. **C2-D 多方块执行器**：玻璃门、滑动门、汽笛及延长段。门须同步上下半、双门、红石和移动方块接口；汽笛须保存高度、音高与动力/流体输入。
5. **C2-E 获取收敛**：逐项转写 Java 配方和战利品；只有依赖链已实现时才开启配方。

## 已交付的 C2-A 起点

`createbedrock:desk_bell` 使用 Java 的空闲/按下模型、原始 `desk_bell.ogg`、六向放置、20 tick 的按压状态、15 级弱输出与附着面的强输出。水和空手交互也在定义中。`createbedrock:rose_quartz_lamp` 已使用 Java 的三态机、16 格簇重置、延迟激活、15 级光照以及 64 种相邻灯输出面组合。两者保留自掉落和创作入口；金板、抛光玫瑰石英等真实来源尚未到位，因此不会伪造 Java 配方。

`createbedrock:stockpile_switch` 使用 Java 的墙面、地面和天花板模型及六档存量贴图。它在世界动态属性中保存过滤器、上下阈值、以堆显示、反相、当前读数和待输出状态；对相邻 Bedrock 原生物品容器及本项目的 Create 流体罐采样，按 Java 的滞回规则切换，并在两 tick 后输出 15 级红石。空手交互打开服务器权威配置表单，持物交互设置过滤器。状态还通过移动结构数据贡献者迁移。

`createbedrock:speedometer` 与 `createbedrock:stressometer` 已开始 C2-B：两者作为无应力的动力传动节点，读取解析后的动力网络并把目标读数保存在 16 档指针状态、颜色状态和 0–15 信号状态中。构建期从 Java 的 gauge base/head/dial 合成 16 套几何，以离散指针替代 Java 的逐帧 Flywheel 插值；速度计沿用默认 30/100/256 RPM 分段，应力计沿用容量/负载和过载 1.125 的计算。Bedrock producer 会直接输出同级信号，而 Java 只对比较器暴露模拟输出；此平台差异须在 Windows 红石矩阵中验证。两者还通过移动结构数据贡献者保留读数状态，但 Java 的 ComputerCraft 外设、工程师护目镜提示与彩色粒子不在 Bedrock Add-On API 范围内。

`createbedrock:display_board` 是 Java `FlapDisplayBlock`（Display Board / Flap Display）的同朝向矩形控制组：最多 32×32 个方块、每行两条并最多 64 条持久化文本。任一成员可打开服务器权威表单；控制组以左下成员为根、同步颜色/发光/手工文本，并在动力网络速度达到 8 后渲染专用文字实体。Display Link 已可向指定行写入原生红石值，控制组状态和移动结构数据会一并迁移。Java 的逐字符翻页动画、客户端 Flywheel 渲染和任意动态源适配仍不能由 Bedrock Add-On 原样表达；当前以 Java 几何与服务器文本标记作为可测试替代。

`createbedrock:placard` 保存一个普通 Bedrock 物品类型：空牌放入一件物品，随后以相同物品交互会刷新 20 tick、15 级红石脉冲；潜行空手交互取回物品，破坏与移动结构也会保留/返还状态。Bedrock 物品 API 不能无损持久化 Java 的 NBT、属性过滤器与完整 ItemStack 组件，所以 v1 仅支持可堆叠物品的 type ID，这项差异必须保持可见。

`createbedrock:stock_ticker` 复用已存在的 Depot 事务日志：持久化网络、地址、九个类型分类、请求物品/数量/部分交付和请求 nonce，表单提交后将一次请求路由到相邻 Depot，并显示 pending/fulfilled/partial/failed 状态。它不伪造 Java 的 Stock Keeper 生物、包装箱/付款库存、属性过滤器或 ComputerCraft 外设；这些依赖尚不存在，因而是后续物流包的明确缺口，而不是已完成的 Java 等价功能。

## C2-C 已交付：时间与铃

`cuckoo_clock` 与 `mysterious_cuckoo_clock` 是动力传动节点：只有速度非零才读取世界绝对时间。主世界沿用 Java 的 12:00–12:04 猪、18:32–18:35 苦力怕窗口；神秘钟改为 101 tick 惊喜动画，并在第 50 tick 移除自身和触发半径 3、破坏方块但不点火的爆炸。时针/分针和动画进度会随移动结构迁移。Bedrock 自定义方块不能直接复用 Flywheel 的局部活动部件，因此当前用状态与声音保留服务器语义；门扇、动物和烟雾的逐帧几何动画须在 Windows 实测后确认可见替代。

`peculiar_bell` 与 `haunted_bell` 具有 74 tick 响铃状态、红石上升沿触发和移动数据迁移。奇异铃放在灵魂火或灵魂营火上会保留后转为闹鬼铃；闹鬼铃以 65 tick 冷却向半径 10 内实体发送灵魂粒子脉冲，并保留手持 10 tick 预热、每 8 tick 半径 3 的脉冲。Java 的客户端网络 `SoulPulseEffectPacket` 和 contraption movement visitor 没有直接的 Bedrock 对应物；当前由服务器粒子与移动数据承载，需平台验证粒子可见性和持物扫描成本。

## C2-D 已交付：门与汽笛

安山、黄铜、铜、玻璃和列车滑动门共享双层状态机：放置时创建上半、相邻反铰链门会成双同步、空手与原生红石都同步上下半开合，移动结构保存开合/供电/铰链状态。打开门移除碰撞并做平移显示。Bedrock 没有 Java `SlidingDoorBlockEntity` 的 Flywheel 实体渲染，故折叠门、分朝向滑移动画和列车 actor 交互仍是明确的实机验收项。

`steam_whistle` 保存大小、供电与 0–24 半音音高；最多六段延长段按 Java 的单段 1、双段 2 半音规则计算。它只在相邻 Create Bedrock 流体罐有内容且有红石时播放导入的高中低原声并发射烟粒子。当前未重做 Java 锅炉热量、pipe organ 成就、墙面完整几何和连续客户端淡入/淡出，这些依赖 C3/S3-12 的平台收敛。

## C2-E 已交付：获取收敛

已转写依赖已存在的布谷钟、神秘布谷钟、奇异铃、三类金属门、列车门和汽笛配方，并为 C2-C/D 方块建立显式掉落、双语、图集、Java 几何/贴图与原声导入契约。闹鬼铃的获取路径是已实现的灵魂火/营火转化；玻璃滑动门因 `framed_glass` 物品链尚未迁移而仅保留创造入口和掉落，不创建替代配方。桌面铃、玫瑰石英灯、库存开关、显示类内容仍各自保留先前记录的未迁移材料/机器依赖，不能因 C2-E 而声称已有完整生存获取。

## 架构约束

玫瑰石英灯的 Java 比较器距离输出可在同一方块的不同面同时取不同值；Bedrock 的原生 redstone producer 只有一个 `power` 值，不能按面分别设定。因此 C2-A 先实现可验证的簇状态/普通输出，再在 Windows 以比较器矩阵验证其可行边界；若 API 无法表达，必须将该差异保留为平台限制，不能声称等价。

本轮已完成 Node 单元/资源契约、构建和包静态校验；Windows、Realm、PS 验收尚未执行，不能把静态通过视为游戏内或主机端通过。

库存开关与 Java 的差异必须保留到实测：Bedrock Script API 不能读取 Forge `ItemHandler` 的每槽容量或第三方流体能力，因此空槽按 64 件计、只支持原生可见物品容器和 Create Bedrock 流体罐；第三方 Java 容器兼容层、绳索滑轮等 `ThresholdSwitchObservable` 目标不在此实现中。其 Java 配方依赖电子管，当前不创建替代配方。
