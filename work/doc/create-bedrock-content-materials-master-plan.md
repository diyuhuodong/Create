# Create Bedrock 内容与材料 116 项主计划

## 目标与边界

本计划覆盖迁移矩阵中尚未 `static_verified` 的 116 条 `phase: 3 / content` 记录：6 条已有实现需收敛，110 条已有来源规格但尚未实现。目标不是注册标识符，而是让每个条目具备可放置或可使用的行为、真实获取路径、资源包和双语文本。Windows、Realm、PS 仍在后续平台验收，不阻塞源码开发。

权威清单为 `bedrock/data/stage3-content-specifications.json`；任何新增或改包必须先更新该清单和迁移矩阵，禁止在代码中绕过台账。

| C2 | 26+ | 时钟、铃、显示板、计量表、汽笛、Stock Ticker，以及重新归类的门和玫瑰石英灯 | S3-14 红石静态回归后 |
| C3 | 5 | 金属支架、金属桁架、转台、木支架 | S3-9 动力运行时 |

## 每包固定三轮

### 第一轮：方块/物品与行为

按包创建 BP 定义、运行时状态、创造栏入口、方块实体持久化或实体生命周期。无状态条目不得暗含脚本依赖；状态条目必须有版本化存档、迁移、移除和重启规则。C6 的移动 actor 与 C7 的实体必须先完成权威服务端语义。

### 第二轮：配方、掉落与获取

逐项读取 Java 配方/掉落来源。全体 110 条规格中有 79 条可候选原版配方、9 条属于世界或战利品路径、22 条没有静态获取配方。后两类不得伪造普通工作台配方：要么接入已迁移的机器/世界生成系统，要么保持显式后置状态，不记作可生存模式获取。

### 第三轮：资源包、语言与可见获取

每个条目补 EN/ZH 名称、贴图、几何、图集映射、配方/掉落表、创造栏或机器获取入口。资源契约同时检查 BP/RP 标识符、构建产物、语言、配方、掉落及实际资源文件；禁止用 full-block fallback 或无来源贴图宣称等价。

## 执行顺序与退出条件

1. C0：补齐 6 条现有内容的获取和资源契约，修正矩阵状态。锌矿现在使用两条地下 ore feature/feature rule 分别在石头层和深板岩层生成，产物经 raw zinc、熔炉和锌块闭环；具体高度和密度仍待实机调参。
2. C1：按“基础材料与构件 → 放置/支撑状态方块 → 食品与仅机器获取物品”三个子批完成三轮。先完成实际无状态内容；门、桌布、玫瑰石英灯等不得作为 C1 空壳注册。
3. C2：在红石静态回归后做持久化显示/仪表/铃/门与玫瑰石英灯内容。
4. C3、C4、C5：按动力、物流、加工依赖顺序接入现有运行时。
5. C6、C7：由 S4/S6 负责；未完成 actor 或实体内核前只维护规格，不注册空壳。
6. 每包代码完成后统一执行 Node 静态测试、`npm run validate`、`npm run build`、`npm run pack`；随后才提升相关矩阵条目。所有包完成后再安排 Windows、Realm、PS 验收。

一个条目的退出条件是：行为和存档正确、获取路径可达、资源与双语完整、源码/构建契约通过。缺失其中任一项时保持 `implementation_in_progress` 或 `specification_pending`。

## 当前实现状态（未验证）

- C0 已补齐锌矿的两套地下 feature/feature rule、矿石掉落、熔炼与储存块闭环；高度与密度仍须在 Bedrock 世界中调参。
- C1-A 已建立 6 个无状态方块资源（黄铜块、铁路/光辉/暗影机壳、两种玫瑰石英瓦）、纸板，以及 5 个原生食物/饮品物品：Java 贴图构建期复用、BP 定义、自掉落、创造栏和 EN/ZH 文本均已添加。纸板保留 50 秒熔炉燃料时长（对应 Java 的 1,000 ticks）；食物保留营养、饱和度、使用时长/动作，建筑工茶还保留急迫与玻璃瓶返还。
- 这 12 项尚未标为生存可获取：分别依赖黄铜混合、物品应用、砂纸抛光、旧版世界转换、压制纸浆、灌装或巧克力加工。资源契约会把这 12 条依赖持续作为显式未完成项，直到真实 Create 获取链接通。
- C1-B 已建立纸板块、绑定纸板块、经验块、经验粒、三种金属梯子、三种金属脚手架与玻璃活板门的 Java 几何/贴图、状态与资源契约：两种纸板保留水平轴和高可燃性；绑定纸板的空原生 loot 表会抑制默认掉落，玩家破坏再按精准采集附魔脚本化选择掉落；爆炸因此保持 Java 的无掉落分支；经验块保留 15 级光照，并以 3–7 tick 的等效平均频率发射中心周围的末地烛粒子；经验粒保留双向九合一合成、主/副手使用、潜行消耗 1 个或通常消耗整叠，以及每个 3 点经验；梯子/脚手架保留每种材质模型、创造入口、自掉落与服务器端垂直移动适配；玻璃活板门保留朝向、上下半、开合、含水、空手交互和原生红石输入，并在放置时同步周围红石强度。经验粒的经验球分裂/飞行/第三方拾取与初始粉碎来源、梯子支撑链/含水、脚手架底部/连通渲染与放置辅助、玻璃活板门的相邻同类连通渲染仍未实现，故这些条目不提升为完成。
